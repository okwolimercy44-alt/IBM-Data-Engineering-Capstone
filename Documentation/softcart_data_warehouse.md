\# SoftCart Data Warehouse – Schema Design



\## 1. Project Overview



This project involves designing a data warehouse for SoftCart, an e-commerce platform that sells digital products, including movies, e-books, and songs.



The purpose of the warehouse is to organise sales data into a dimensional model that supports analytical queries, reporting, and business decision-making.



The schema was designed using the Entity Relationship Diagram (ERD) tool in pgAdmin 4 and implemented in PostgreSQL.



\## 2. Data Warehouse Design



The warehouse uses a \*\*Star Schema\*\* design consisting of four dimension tables and one fact table.



The dimension tables provide descriptive information about sales, while the fact table records individual sales transactions and their associated measurements.



\### 2.1 Dimension Tables



\*\*softcartDimDate\*\*



Stores date-related information to support analysis across different time periods.



Columns:

\- dateid – Primary key

\- date – Calendar date

\- year – Calendar year

\- quarter – Quarter of the year

\- month – Month number

\- monthname – Month name

\- day – Day of the month

\- weekday – Weekday number

\- weekdayname – Weekday name



\*\*softcartDimCategory\*\*



Stores product category information.



Columns:

\- categoryid – Primary key

\- category – Product category



\*\*softcartDimItem\*\*



Stores information about the individual products sold.



Columns:

\- itemid – Primary key

\- item – Product name



\*\*softcartDimCountry\*\*



Stores the countries associated with sales transactions.



Columns:

\- countryid – Primary key

\- country – Country name



\### 2.2 Fact Table



\*\*softcartFactSales\*\*



Stores sales transaction records and connects the four dimension tables.



Columns:

\- orderid – Primary key identifying each order

\- dateid – Foreign key referencing softcartDimDate

\- categoryid – Foreign key referencing softcartDimCategory

\- itemid – Foreign key referencing softcartDimItem

\- countryid – Foreign key referencing softcartDimCountry

\- Price – Numerical sales amount



\## 3. Primary Keys and Foreign Keys



Primary keys uniquely identify records in each table.



The following primary keys were created:



| Table | Primary key |

|---|---|

| softcartDimDate | dateid |

| softcartDimCategory | categoryid |

| softcartDimItem | itemid |

| softcartDimCountry | countryid |

| softcartFactSales | orderid |



Four foreign-key relationships were established between the fact table and the dimension tables:



1\. `fk\_sales\_date`: FactSales.dateid → DimDate.dateid

2\. `fk\_sales\_category`: FactSales.categoryid → DimCategory.categoryid

3\. `fk\_sales\_item`: FactSales.itemid → DimItem.itemid

4\. `fk\_sales\_country`: FactSales.countryid → DimCountry.countryid



Each dimension table has a one-to-many relationship with the fact table.



\## 4. Schema Implementation



The tables and relationships were designed in the pgAdmin 4 ERD tool.



The generated SQL script was executed successfully in the PostgreSQL `staging` database.



The implementation created:

\- Four dimension tables.

\- One fact table.

\- Five primary-key constraints.

\- Four foreign-key constraints.



\## 5. Project Files



The supporting implementation files are maintained in this Documentation folder:

\## 6. Conclusion



The SoftCart data warehouse schema provides a structured foundation for analysing sales across products, categories, countries, and dates.



By separating descriptive attributes into dimension tables and connecting them through a central fact table, the design supports multidimensional analysis and subsequent reporting tasks.
